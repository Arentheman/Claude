# Бот для Doodle Jump (Telegram mini-app)

Бот смотрит на экран, находит героя, платформы, монстров и чёрные дыры
и сам управляет игрой клавишами A/D и пробелом. Играет, пока его не
остановишь, а после падения сам нажимает «Играть заново».

## Быстрый старт (без установки)

1. Скачай `DoodleBot.exe` из папки `releases/` этой ветки. Python ставить не нужно.
2. Запусти его. Windows может показать «Система Windows защитила ваш
   компьютер»: нажми «Подробнее» → «Выполнить в любом случае». Так бывает
   со всеми программами без цифровой подписи. Первый запуск занимает
   5–10 секунд: программа распаковывается.
3. Открой игру в Telegram. Окно игры потом не двигай и не меняй его размер.
4. В окне бота нажми **«Выбрать область игры…»**. Экран затемнится:
   обведи мышкой игровое поле, без заголовка окна Telegram.
5. Справа появится картинка с разметкой: платформы зелёные, герой синий,
   монстры красные, дыра в фиолетовом круге. Если всё обведено, область
   выбрана верно.
6. Нажми **«Старт»**. Бот сам кликнет по игре, чтобы она стала активной,
   и начнёт играть. **F8** ставит на паузу и запускает снова в любой момент.

Окно бота не должно закрывать игру: бот смотрит на экран. При старте
он сам отодвигает своё окно, если хватает места.

Настройки сохраняются в `%APPDATA%\DoodleBot\config.json`.

### Настройки в окне

- **Бросок оружия.** «Пробелом» стреляет, только когда монстр прямо
  над головой. «Кликом по монстру» подходит, если оружие летит в сторону
  курсора.
- **Сам нажимать «Играть заново»** после падения.
- **Показывать, что видит бот.** Живая картинка с разметкой.
- **Задержка реакции.** Если бот часто промахивается мимо платформ,
  сдвинь вправо (80–120 мс).

## Запись для разбора ошибок

1. В окне бота поставь галочку **«Записывать игру бота»**.
2. Нажми «Старт» и дай боту сыграть, например, 10 попыток.
3. Нажми «Пауза» (или F8). Бот упакует запись в zip и сам откроет папку
   с ним: `Документы\DoodleBot recordings\rec_<дата>.zip`.
4. Пришли этот zip. 10 попыток занимают примерно 15–30 МБ.

Что внутри:

- `deaths/attempt_NN.mp4` — последние 8 секунд перед каждым падением,
  с разметкой: что бот распознал, куда целился, какие клавиши жал;
- `timeline.mp4` — вся сессия в уменьшенном виде;
- `telemetry.jsonl.gz` — по каждому кадру позиции объектов, скорость
  героя, цель и решения бота;
- `summary.json` — сколько длилась каждая попытка и на какую высоту дошёл бот.

## Запуск из исходников (для разработки)

```
pip install -r requirements.txt
python app.py                 # то же окно
python bot.py --calibrate     # консольный вариант: калибровка по F7
python bot.py                 # консольный вариант: F8 старт/пауза, F10 выход
```

Пересобрать exe на Windows:

```
pip install -r requirements.txt pyinstaller
pyinstaller DoodleBot.spec    # результат: dist\DoodleBot.exe
```

## Как он играет

- **Зрение** (`vision.py`). Кадр приводится к ширине 488 px, как на
  записи экрана. Объекты отделяются от плавного фона, а потом
  различаются по цвету и форме. Героя бот ищет по шаблонам из `templates/`.
- **Решения** (`planner.py`). Бот знает физику прыжка: высота около
  145 px, горизонтальная скорость около 380 px/с. Во время игры он
  уточняет эти числа сам. Каждый кадр он выбирает самую высокую
  платформу, до которой успеет долететь. Учитывает проход сквозь края
  экрана, движущиеся платформы и задержку между кадром и нажатием.
  Платформы с бонусами (пружина, буст, ракета) ему выгоднее.
- **Безопасность.** Перед каждым нажатием бот прогоняет следующие
  ~0.75 с полёта, включая отскоки, и не идёт туда, где окажется
  рядом с центром чёрной дыры или врежется в монстра снизу или сбоку.
  Прыгнуть на монстра сверху безопасно, это разрешено.
- **Стрельба.** Монстр прямо над головой — бросок пробелом.
- **Если застрял** (прыгает на месте, потому что путь вверх закрыт),
  бот пробует рискованные дальние прыжки. Если над единственным путём
  висит монстр, встаёт под него и сбивает.

## Настройки (`config.json`)

| Параметр | Что делает |
|---|---|
| `"throw": "space"` | бросок пробелом (по умолчанию) |
| `"throw": "click"` | бросок кликом ЛКМ по монстру (если оружие летит в сторону курсора) |
| `"key_left"`, `"key_right"` | клавиши движения (по умолчанию `a` и `d`) |
| `"restart": false` | не нажимать «Играть заново» автоматически |
| `"physics": {"latency": 0.08}` | задержка реакции, с. Увеличь, если бот промахивается мимо платформ |
| `"physics": {"run_speed": 380, "jump_speed": 785}` | стартовые значения физики |
| `"planner": {"apex_margin": 10}` | запас по высоте при выборе платформы, px |
| `"planner": {"hole_radius_k": 0.25}` | размер опасной зоны вокруг чёрной дыры |

Пример:

```json
{
  "region": {"left": 700, "top": 120, "width": 488, "height": 1080},
  "throw": "space",
  "physics": {"latency": 0.06}
}
```

## Если что-то не работает

- **Бот не нажимает клавиши.** Окно игры должно быть активным (кликни по
  нему). Если не помогает, запусти командную строку от имени администратора.
- **Героя или платформы не видно** на `calibration_check.png`. Проверь, что
  область выбрана точно по краю игры. Если дело в ночном фоне, запиши
  короткое видео ночного участка и прогони его:

  ```
  python analyze_video.py запись.mp4 результат.mp4
  ```

  Если на записи весь экран, укажи область игры: `--crop x,y,ширина,высота`.
  В `результат.mp4` видно, что бот распознал на каждом кадре. Пороги
  цветов собраны в начале `vision.py`.
- **Бот часто промахивается.** Увеличь `physics.latency` до 0.08–0.1.
- **Бот медленный.** В консоли раз в 5 секунд печатается скорость.
  Нормально 30 к/с и выше.
